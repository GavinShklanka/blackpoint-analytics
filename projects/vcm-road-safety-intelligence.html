Nova Scotia Road Safety Intelligence

Collision severity analytics for corridor prioritization and public-safety decision support

Open GitHub ← All Projects

Executive Summary

This project transforms raw Nova Scotia collision data into a structured analytical product that supports public-safety planning. It combines vehicle collision modeling with interactive dashboards to surface severity patterns, identify high-risk corridors, and support evidence-based resource allocation decisions.

The system demonstrates how applied analytics can translate a real-world public-interest problem into a decision-support tool that is interpretable, structured, and operationally useful.

Business Problem

Road safety agencies face a fundamental analytical challenge: collision data is abundant but understructured. Without clear severity classification, corridor-level risk profiles, and interpretable visualizations, decision-makers struggle to prioritize interventions.

The gap is not missing data — it is missing analytical workflow between raw records and actionable intelligence. Current approaches tend to produce either oversimplified summary statistics or overwhelming volumes of unprocessed records, neither of which directly supports operational planning.

Solution Overview

The system ingests collision records, applies bootstrap-based severity modeling to classify risk levels, and presents results through an interactive dashboard with corridor-level drill-downs, temporal pattern views, and severity distribution analysis.

The workflow moves from raw data through statistical modeling to stakeholder-facing analytics — creating a structured pipeline that makes the analytical process transparent and the outputs usable.

What I Did

Designed the analytical workflow end-to-end: data ingestion pipeline, bootstrap severity classification model, interactive dashboard architecture, corridor prioritization logic, and the interpretive framing that makes statistical outputs usable for operational planning.

Built the visualization layer to communicate risk patterns clearly to non-technical stakeholders. The emphasis was not just on producing accurate models, but on making those models interpretable and the overall analytical process navigable.

Technical Architecture

Data Layer

CSV/structured collision records → cleaned and normalized pipeline

Modeling

Bootstrap resampling for severity classification, confidence intervals, corridor scoring

Frontend

Interactive JavaScript dashboard with filtering, drill-down, and map views

Outputs

Severity heatmaps, corridor risk profiles, temporal trend analysis, priority rankings

System Workflow

  1. Ingest and clean raw collision records

  2. Apply bootstrap severity classification model

  3. Generate corridor-level risk scores and confidence intervals

  4. Build interactive dashboard with filtering and drill-down

  5. Present stakeholder-facing severity patterns and recommendations

Outcomes

  • Structured severity classification across thousands of collision records
  • Corridor-level risk profiles with statistical confidence bounds
  • Interactive dashboard supporting temporal and geographic drill-downs
  • Decision-support framework for resource prioritization

Reflection & Next Phase

The next phase would integrate real-time data feeds, expand the severity model to include environmental and behavioral covariates, and develop a predictive layer for emerging risk corridors. The governance framework — ensuring model outputs are interpretable and claim-bounded — would remain central to any expansion.
